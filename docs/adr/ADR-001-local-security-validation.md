# ADR-001: 用戶端資料安全與防禦性驗證機制

## 狀態
已接受 (Accepted)

## 上下文
在之前的版本中，考試系統存在以下安全隱患：
1. 題庫載入路徑可透過 URL 的 `bank` 參數或題庫選擇器進行任意注入，可能載入非預期的本地檔案。
2. LocalStorage 中的考試進度（`examProgress`）與歷史紀錄（`examRecords`）在恢復時，未經任何資料結構與欄位驗證便直接展開或讀取，這可能導致因資料格式被惡意篡改或損毀而引發的系統邏輯異常或崩潰。
3. 載入配置時使用不安全的物件展開合併（`{ ...config, ...savedConfig }`），容易遭受原型污染（Prototype Pollution）或配置狀態污染。
4. 原本的內容安全政策 (CSP) 允許了 `data:` URI，增加了敏感資料外洩的風險。

為了加強作為純前端練習工具的穩定性與安全性，我們需要在用戶端實施防禦性編程。

## 決策
我們決定在 `app.js` 中引入以下安全控制與驗證機制：
1. **題庫白名單限制**：定義靜態白名單 `ALLOWED_BANKS`。在載入與切換題庫時，嚴格比對檔名，僅允許載入白名單內定義的 JSON 題庫檔案，從根本上阻擋路徑注入。
2. **LocalStorage 進度與歷史結構驗證**：新增 `_validateProgressSchema()` 與 `_validateRecordsSchema()` 方法，在從 LocalStorage 讀取資料前，逐一驗證陣列結構、各欄位的資料型別、長度與合法範圍。若驗證失敗，自動清除異常資料，確保系統不崩潰。
3. **配置清理與驗證**：新增 `_sanitizeConfig()` 方法，取代原先的物件展開合併。該方法逐欄驗證設定值的型別與合法範圍，確保外部傳入的設定不會破壞系統預設行為。
4. **收緊 CSP 政策**：移除內容安全政策 (CSP) 中 `img-src` 與 `font-src` 的 `data:` URI 支援，僅允許 `'self'`。
5. **安全觸發下載**：檔案匯出不再將 `<a>` 元素插入 DOM，改為透過 `dispatchEvent(new MouseEvent(...))` 觸發下載，避免潛在的 DOM 污染與 XSS 機會。

## 後果
- **好處**：
  - 顯著提升系統的穩定性，防止使用者因 LocalStorage 資料損毀而無法使用系統。
  - 阻斷了透過 URL 參數載入惡意本地檔案或非預期 JSON 的路徑注入漏洞。
  - 提升了網頁的整體安全防護等級，減少 XSS 與敏感資料外洩的機會。
- **壞處/限制**：
  - 每次新增題庫檔案時，除了修改 `index.html` 外，開發者必須手動將新檔名加入 `app.js` 中的 `ALLOWED_BANKS` 白名單，增加了額外的開發維護步驟。
